# デプロイメントと開発フロー

[← ドキュメント一覧](./README.md) | 言語: **日本語** | [English](../en/deployment.md)

## デプロイメント

Bracify の公開方法は、次の 2 通りです。特定のサービス（Vercel・Netlify など）向けの機能や、Zip でのエクスポートはありません。

- **静的サイトとして公開（CLI ビルド）**: `node cli/index.js <入力フォルダ> <出力フォルダ>`（`cli` パッケージをインストールすれば `bracify` コマンドとしても実行できます）で、`data-t-include` を解決した静的な HTML を出力フォルダに書き出します。`_` で始まるフォルダ・ファイル（`_parts`・`_sys`）は出力されず、`bracify.js` が出力フォルダ直下に置かれるため `file://` でも動作します。出力は静的で読み取り専用です。Data API（`/_sys/data/*.json`）は含まれないため、フォームのデータ保存はできません。`data-t-source` のデータは、入力フォルダ直下に `mock-data.json` がある場合のみ、その内容でビルド時にバインドされます。静的ファイルを配信できるホスティングであれば、どこでも公開できます。
- **サーバーとして公開（サーバーモード）**: `node engine/start.cjs <プロジェクトのパス> [ポート]` でサーバーを起動します。データの保存には SQLite（`_sys/data.db`）を使用するため、Node.js が動作し、ファイルをディスクに保持できるホストが必要です。ファイルシステムが一時的なサーバーレスのプラットフォームには向きません。

**既知の制限**:

- ワンステップのデプロイ機能は [#105](https://github.com/tri-comma/Bracify/issues/105) で対応を予定しています。
- Data API には認証がありません。公開サーバーに到達できる人は、データの作成・更新・削除ができます（現状の保護は[クロスオリジン保護](security.md#セキュリティ)のみで、認証ではありません。[#106](https://github.com/tri-comma/Bracify/issues/106) で対応を検討中）。公開する場合は、この点に注意してください。

## 開発フロー

現時点では、配布済みのインストーラーはありません。Studio はリポジトリから起動します。

1. Node.js をインストールし、リポジトリを取得して、ルートで `npm install` を実行します（Studio 用の Electron と、SQLite のネイティブモジュールがセットアップされます）。
2. ルートで `npm start` を実行して、Studio（Launcher）を起動します。
3. Launcher で作業フォルダを選択してサーバーを起動し、Admin Dashboard を開きます。
4. `index.html` や `_parts/header.html` などを編集します。保存すると、サーバーが変更を検知して反映します。
5. 公開するときは、上の「デプロイメント」のとおり、CLI で静的にビルドするか、Node.js が動くホストでサーバーモードを動かします。

Studio を使うためのターミナル操作は、手順 1〜2 の起動だけです。起動後のサイト作りに、ターミナルや設定ファイルは必要ありません。Studio が各プロジェクトのサーバーを起動するときは、Studio 自身の実行環境（Electron）を使うため、プロジェクトの実行に別途 Node.js は不要です。CLI（静的ビルド）は任意で、使う場合は Node.js が必要です。
